# English Game Builder

## 目標與使用範圍

把國中英文學習目標轉為可實際遊玩的冒險遊戲，兼顧教師操作、學習回饋與精緻視聽體驗。所有教師操作說明、錯誤提示、部署文件與測試步驟使用繁體中文；題目、例句與必要的遊戲對話可使用符合年級程度的英文。

只有在使用者要求製作或修改遊戲時才開始實作。若任務僅為建立或審查 Skill，僅處理技能文件，不建立遊戲、安裝遊戲依賴或部署網站。

## 執行流程

1. 閱讀專案的 `AGENTS.md`、README、套件與部署設定，保留既有使用者變更，優先沿用現有技術與測試工具。
2. 從教材或需求確認年級、學習目標、題量、關卡主題及使用情境。能合理推定的項目採用明確預設；只有缺失會阻礙實作時才提問。未提供教材時使用原創示範題，標明示範用途。
3. 先規劃核心循環：探索場景 → 互動／接任務 → 作答 → 解說與獎勵 → 更新進度 → 解鎖關卡。列出四類關卡、視覺方向、資料格式及驗收條件，再持續完成實作。
4. 優先完成一個可玩的完整流程，再擴展到四類關卡與教師功能。選擇適合專案的 2D 引擎或 Canvas／DOM 技術；不要只交付按鈕問答頁或靜態視覺稿。
5. 執行功能、跨裝置、無障礙、資料與建置驗證，修正環境或實作問題。交付繁體中文操作文件、測試結果與已知限制，區分已驗證與未驗證項目。

## 必備功能與品質標準

### 奇幻場景、動畫與互動

- 建立風格一致的精緻 2D 奇幻世界：分層背景、前景、可探索路徑、地標、角色與清楚的介面層級；避免素材風格混雜。
- 提供角色待機與移動動畫，以及互動、答對、答錯、獲得獎勵和解鎖關卡的視覺回饋。特效不得遮蔽題目或依賴高頻閃爍。
- 遊戲狀態與畫面同步；限制粒子數量、回收資源並避免重複註冊事件。支援 `prefers-reduced-motion`，讓使用者減少非必要動畫。
- 載入時顯示進度；素材載入失敗時有替代畫面與可理解的錯誤提示，不能留下空白畫面。

### 背景音樂與音效

- 提供適合課堂的循環背景音樂、答對／答錯及互動音效；提供清楚可見的聲音開關，保存使用者偏好。
- 遵守瀏覽器自動播放限制：首次點擊或觸控後才啟用音訊。切換頁面或暫停時妥善處理音訊，避免重疊播放。
- 將背景音樂、效果音及聽力題音訊分開控制；播放聽力題時降低或暫停背景音樂。靜音不能造成不可理解的測驗狀態。

### 四類英文關卡

- 單字：情境辨義、圖文配對或拼字任務；提供詞義、例句與錯誤回饋。
- 文法：使用符合國中教材的句型與情境題，答後解釋正解與常見誤解。
- 閱讀：提供適齡短文，涵蓋主旨、細節、指涉或推論；讓學生在作答時能重新查看文章。
- 聽力：提供可重播音訊與播放狀態，處理載入失敗。逐字稿在練習模式或答後顯示，測驗前不直接洩漏答案。
- 題目必須有唯一明確正解、合理干擾選項與教師可理解的解析。提供練習／測驗模式，清楚說明重試、提示、計分與播放限制。
- 若採瀏覽器語音合成，檢查英文語音是否可用並提供音檔替代方案；不可宣稱不同裝置的語音或離線能力完全一致。

### 手機、平板與電腦

- 支援觸控、滑鼠及鍵盤；手機不依賴滑鼠懸停。互動目標原則上至少 44 × 44 CSS px，文字可讀且不被安全區或虛擬鍵盤遮住。
- 處理直向、橫向、視窗縮放與高像素密度螢幕；維持場景比例與正確的點擊座標，不裁切關鍵介面。
- 提供鍵盤焦點、可辨識標籤、足夠對比及文字狀態回饋。Canvas 遊戲須提供可操作的 DOM 題目與控制介面。

## 教師題庫匯入

提供教師操作入口、JSON／CSV 範本、匯入預覽與逐筆錯誤報告。先驗證整批資料，通過後才套用；失敗不得破壞現有題庫。題目資料以純文字呈現，不直接插入不可信 HTML。

優先相容專案既有資料格式；新專案採用下列契約，所有範例均為資料規格，不代表此 Skill 已附帶遊戲實作。

```json
{
  "version": 1,
  "questions": [
    {
      "id": "vocab-001",
      "type": "vocabulary",
      "prompt": "Which word means 圖書館?",
      "choices": ["library", "hospital", "market", "station"],
      "answerIndex": 0,
      "explanation": "library 是圖書館。",
      "points": 10,
      "level": "grade7",
      "passage": "",
      "audioUrl": ""
    }
  ]
}
```

- `type` 限定為 `vocabulary`、`grammar`、`reading` 或 `listening`；`answerIndex` 從 0 起算。`id` 不得重複，分數為非負有限數值。
- CSV 使用 UTF-8，支援 BOM、引號、逗號與欄位內換行。欄位為 `id,type,prompt,choiceA,choiceB,choiceC,choiceD,answerIndex,explanation,points,level,passage,audioUrl`，將選項映射為 `choices`；不要用單純的逗號切割解析 CSV。
- 範本採四選一；驗證必要欄位、非空選項、答案範圍、檔案大小及題數上限。閱讀題必須有文章，聽力題必須有可用音檔或明確支援的語音來源。
- 限制遠端素材 URL 為 HTTPS，或允許明確定義的同站相對路徑。拒絕不支援的協定，處理跨來源音訊限制；不從題庫執行程式碼。
- 匯出 CSV 時處理以 `=`, `+`, `-`, `@` 開頭的欄位，避免試算表公式注入。文件說明欄位格式、限制與修正範例。

## 學生資料、得分與排行榜

- 支援學生暱稱、每題作答結果、得分、關卡進度與排行榜；使用版本化儲存格式。預設只收集必要資料，不要求真實姓名、電子郵件或其他識別資料。
- 本機儲存需處理損毀資料、容量不足與不可用狀態，提供重設進度功能與確認提示。共用裝置能切換暱稱且不混用學生進度。
- 明確定義重複作答、重試、提示扣分、同分排序與完成判定，避免重整或重複點擊重複加分。
- 區分「此裝置排行榜」與「班級共享排行榜」。共享排行榜必須使用後端資料與驗證；純前端分數可遭修改，不可宣稱具有防作弊保證。

## Google Apps Script 成績串接

- 以獨立資料介面實作選配串接；未設定端點時保留可玩的本機模式，清楚顯示同步狀態。
- 與教師確認或提供版本化請求契約，例如 `schemaVersion`、`submissionId`、`nickname`、`quizId`、`score`、`maxScore`、`completedAt` 及必要的作答摘要。限制欄位與大小，避免記錄多餘學生資訊。
- Apps Script 端驗證資料、分數範圍與題庫版本，使用 `submissionId` 去重；共享表格寫入需處理併發。機密只能放在伺服器設定中，不能放入前端或題庫。
- 驗證已部署 Web App 的實際請求格式、重新導向與 CORS 行為。選擇可讀取確認回應的整合方式；必要時使用 Cloudflare Pages Functions 代理並限制可用目的地。
- 不以 `fetch` 的 `no-cors` opaque 回應當成成功回傳的證據。設定逾時、有限重試及待同步佇列，只有收到可驗證確認才標記同步完成。
- 文件提供 Apps Script 部署、存取權限、試算表欄位與測試步驟。沒有有效端點時使用 mock 測試並標明尚未完成真實端到端驗證，不索取聊天中的機密。

## 素材與授權

- 優先採用免費且合法授權的素材，例如 CC0 或允許本用途的開放授權素材；逐項核實來源與條款，不能把「可免費下載」等同於可再散布。
- 建立素材清單，記錄檔名、作者、來源網址、授權、署名要求與修改情形，涵蓋圖像、字型、音樂及音效；隨專案保存必要的授權文件。
- 避免未授權教材掃描、商業遊戲角色、音樂或來源不明素材。不確定授權時改用原創或已確認授權的替代品。

## Cloudflare Pages 部署

- 優先提供可部署的靜態前端，依現有框架記錄確切建置命令、Node.js 版本、輸出目錄與相對素材路徑；有 SPA 路由時驗證直接開啟深層路徑與重新整理。
- 本機執行正式建置並驗證產物，不將開發伺服器可運作視為部署成功。確認行動裝置載入、HTTPS 音訊、大小寫路徑與素材快取更新。
- 若需要 Pages Functions，分別說明伺服器與前端設定。前端建置變數屬公開資訊，禁止放入機密；在 Cloudflare 的伺服器端設定中安全配置必要機密。
- 提供繁體中文 Git 整合或直接上傳部署步驟、更新方式與回復方式。部署至外部服務須符合使用者授權；未實際部署時明確標示只完成部署準備。

## 測試與交付

依專案工具加入有意義的自動化驗證，並提供教師可重現的人工測試流程。至少涵蓋：

1. 首次載入、素材失敗、開始遊戲、移動、互動、暫停及完成關卡；確認動畫和回饋符合操作結果。
2. 四類題目各完成答對、答錯、解析與重試；檢查計分、解鎖條件及防止重複加分。
3. 音樂／音效開關、聽力播放與重播、首次互動限制、音訊失敗及設定保存。
4. 有效 JSON 與含引號、逗號、換行、BOM 的 CSV；無效題型、缺欄、重複 ID、答案越界、過大檔案及不安全文字。確認匯入失敗保留原題庫。
5. 暱稱切換、重新載入後進度、重設、同分排序與儲存損毀。共享排行榜另測後端讀寫與資料隔離。
6. Apps Script 成功、拒絕、逾時、離線與重複提交；檢查去重及失敗時不顯示成功。區分 mock 與真實端點驗證。
7. 手機直向（例如 360 × 800）、平板（768 × 1024）及桌面（1440 × 900）的操作與縮放；確認觸控、鍵盤、焦點和減少動畫模式。註明模擬裝置與實機測試的差別。
8. 正式建置、產物啟動、素材及路由請求；實際部署後再驗證 Cloudflare Pages 上的核心流程。未執行的檢查列為未驗證。

交付新增／修改檔案清單、啟動與建置命令、題庫範本、素材授權清單及繁體中文教師指南。指南需涵蓋學生開始遊戲、教師匯入題庫、計分設定、聲音、排行榜、資料重設、成績串接、部署及常見問題。報告實際測試結果與剩餘限制，不以靜態檢查冒充完整遊玩驗證。
